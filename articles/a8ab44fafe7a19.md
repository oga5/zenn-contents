# マルチエージェント型ゲーム開発システム GameStudio 1984 の開発

## 1. システム概要

GameStudio 1984は、1984年のゲーム開発スタジオを現代によみがえらせることをコンセプトにした、自律型AIエージェントによるゲーム制作システムです。このシステムではマルチエージェントシステムを採用し、企画からプログラミング、グラフィック、サウンド、テストに至るまで、役割の異なる6つのエージェントが連携してHTML5ゲームを自動生成します。
本システムの開発はマルチエージェントシステムの試作をとおして、エージェント間の連携やFunction Callingの安定実行を実現するための実装手法を習得するために実施しました。

### 対象ユーザー

- マルチエージェントシステムの実装を検討している人

### 基本仕様
- **入力**：自然言語によるゲームコンセプトの記述
- **出力**：HTML5 / JavaScript / PNG（画像）/ WAV（音声）で構成されるプレイ可能なゲーム一式
- **アーキテクチャ**：LangChainによるマルチエージェント・オーケストレーション
- **LLM**：gemini-2.5-flash-lite-preview-09-2025 / gemini-3-flash-preview

LangChainエージェント群は同一GCEインスタンス上のLiteLLMを経由してGemini APIを呼び出す。LiteLLMがプロキシとして介在するこ
とで、モデルの切り替えやリトライ制御を一元管理している。また、APIキーをLiteLLM側で一括管理することで、エージェントのプロ
ンプトやログからAPIキーが流出するリスクを排除している。

### システムの構成要素
1. **Manager** — ワークフローを動的に生成し、各エージェントのタスク実行を管理する。
2. **Designer** — ゲーム仕様（design.json）とアセット定義を策定する。
3. **Graphic Artist** — 独自DSLを用いてドット絵（スプライト）を生成する。
4. **Sound Artist** — パラメータ指定による波形合成で効果音を生成する。
5. **Programmer** — gamelib.jsを用いてゲームロジックを実装する。
6. **Tester** — ヘッドレスブラウザで自動実行検証を行う。

## 2. ワークフロー制御

本システムは、品質と一貫性を確保するためにアセットファースト・ワークフローを採用している。コードの実装に先立って全アセッ
トを確定させることで、「存在しないファイルを参照する」類のエラーを構造的に排除する。

### 実行フェーズ
1. **デザイン** — ゲームルール、オブジェクト定義、アセットリストを策定する。
2. **アセット制作** — 実装に先立ち、全画像・音声ファイルを生成して確定する。
3. **実装** — 確定済みのアセット情報を定数として組み込み、ゲームロジックを記述する。
4. **テスト** — 実行時エラーを検知し、自動修正ループを回す。

### 依存関係の管理
ワークフローはJSON形式で定義され、各タスクは先行タスクの完了を条件に実行される。この依存関係の明示により、画像や音声の欠
落に起因するランタイムエラーを未然に防いでいる。

・ファイル操作のツール群

### 3.1 アセット生成ツール

#### ドット絵生成：doteditor（`generate_image`）

小型のスプライト（32x32未満）に適したピクセルアート生成ツール。

1. **データ記述** — LLMが16進数カラーコードとASCII文字（A〜Z, a〜f で最大32色）を対応させたパターン文字列を出力する。ラ
ンレングス圧縮（RLE）にも対応し、`A16B16` のように繰り返しを簡潔に記述できる。
2. **レンダリング** — `dotter.py` がPillowライブラリでパターンを解析し、PNG画像に変換する。
3. **統合** — `combine.py` が個別スプライトを単一のスプライトシートに最適配置して統合する。

このツールはLLMがAAABBBBのようにビットパターンを出力して、pythonでPNGを生成するが、LLMはこのような出力は得意としておらず
、大きいサイズのスプライト生成はうまくいかず、SVG経由でPNGを出力するツールを追加した。

#### SVG→PNG変換：`generate_svg`

背景・UI要素・大型キャラクターなど、64x64以上の複雑なグラフィックに適した生成ツール。

1. **データ記述** — LLMがSVGマークアップを直接出力する。ドット絵では表現しにくいグラデーションや複雑な図形を扱える。
2. **レンダリング** — `resvg_py` ライブラリがSVGをラスタライズし、PNG形式に変換する。XMLネームスペースの自動補完やPNGヘ
ッダの検証も行う。
3. **ループ検知** — 同一SVGの繰り返し投入をMD5ハッシュで検知し、無限ループに陥ることを防止する。

#### サウンド合成：synthesizer（`generate_sound`）

BGMや複雑な音響に適したトラックベースの音声合成ツール。

1. **パラメータ定義** — LLMがBPM・パターン長・トラック構成をJSONで出力する。
2. **トラックタイプ** — ドラム（Kick / Snare / Hi-Hat / Clap）、オシレータ（Sine / Square / Sawtooth / Triangle）、コー
ド、FM合成の4種類をサポートする。
3. **音声合成** — `synth.py` が上記パラメータに基づいてサンプリングデータを数値計算し、WAV形式で書き出す。

#### 効果音プリセット：`generate_sfx`

ゲームでよく使われる効果音を、プリセットの指定だけで即座に生成できる簡易ツール。JSONパターンの記述は不要で、種類・強度・
ピッチの3パラメータのみで制御する。

| プリセット | 用途 |
|:--|:--|
| `explosion` | 爆発音（サブベース + ノイズ） |
| `laser` | レーザー発射（高→低ピッチスイープ） |
| `hit` | 打撃・衝突音 |
| `jump` | ジャンプ（上昇ピッチスイープ） |
| `coin` | アイテム取得（2音チャイム） |
| `powerup` | パワーアップ（上昇アルペジオ） |
| `gameover` | ゲームオーバー（下降メロディ） |
| `victory` | 勝利ファンファーレ |
| `damage` | ダメージ（下降バズ音） |
| `select` | メニュー選択（短いブリップ） |
| `blip` | シンプルなビープ音 |

### 3.2 ファイル操作ツール

エージェントがプロジェクト内のファイルを操作するためのツール群。すべてのパスはプロジェクトルートからの相対パスとして解釈
され、`../` によるパストラバーサルやシンボリックリンクを用いたディレクトリ外へのアクセスは遮断される。
LangChainが提供しているファイル編集ツールはGemini Flashモデルとの相性がよくないのかファイル編集を失敗するケースが観察されたため、独自のツール群として実装した。

| ツール | 機能 | 備考 |
|:--|:--|:--|
| `read_file` | ファイルの読み取り | 行範囲の指定が可能 |
| `file_edit` | 文字列の完全一致による部分置換 | 対象が一意でない場合はエラー |
| `sed_edit` | 正規表現による置換 | キャプチャグループ対応 |
| `write_file` | 新規ファイルの作成 | 既存ファイルがある場合はエラー |
| `replace_file` | ファイル全体の上書き | 既存ファイルの完全置換 |
| `copy_file` / `copy_dir` | ファイル・ディレクトリのコピー | — |
| `mv_file` | ファイルの移動・リネーム | — |
| `list_directory` | ディレクトリ一覧の取得 | 再帰オプションあり |
| `glob_search` | globパターンによるファイル検索 | 例: `**/*.js` |
| `grep_search` | 正規表現によるファイル内容検索 | ファイルタイプで絞り込み可能 |
| `inspect_image` | PNG画像のメタデータ取得 | サイズ・ファイル容量 |
| `inspect_audio` | WAV音声のメタデータ取得 | 再生時間・無音検知 |

`file_edit` はエージェントが最も多用するツールであり、対象文字列がファイル内で一意に特定できることを要求する。複数箇所に
マッチした場合はエラーとなるため、LLMの文脈誤認によるコード破壊を防ぎ、安全な差分更新を実現している。


### 3.3 自動検証：firefoxtester

1. **実行環境** — SeleniumまたはPlaywrightを介してFirefoxブラウザをヘッドレスで起動する。
2. **ログ監視** — ブラウザコンソールをリアルタイムに監視し、JavaScript例外をキャプチャする。
3. **修正フィードバック** — 検知したスタックトレースをProgrammerエージェントに再投入し、エラーの自動修正を試みる。
